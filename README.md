# jins-forum — KMBP FORUM (вторая половина проекта)

Форум / соцсеть: лента, разделы, посты, комментарии, группы, каналы, стикеры, GIF, личные сообщения, профили.
Подробное описание функций — `FORUM.md`.

Это **отдельный сервис**, который работает с **той же базой данных**, что и бот (`jins-bot` на Render): аккаунты, профили, значки,
отзывы, личные сообщения («Поддержка» и чаты — те же, что в мини-аппе), блокировки и права админов общие. Всё работает как раньше,
просто в двух процессах.

## Что внутри
| Файл | Назначение |
|---|---|
| `main.py` | точка входа: подключение к БД, запуск веб-сервера форума |
| `forum.py`, `forum_groups.py`, `forum_gifs.py`, `forum_names.py` | сам форум (API `/forum/api/*`, группы, GIF, ссылки `exg/имя`) |
| `forum.html` | клиент форума (собран из `forum.src.html`) |
| `forum_calls.py` | звонки: личные и групповые, аудио/видео (WebRTC; сервер только передаёт сигналы) |
| `tools/chatstyle/` | оформление чатов: обои, цвета и форма пузырей, размер текста (`chatstyle.js` + `chatstyle.css`, подключаются в `forum.src.html` через `{{inc:…}}`) |
| `tools/music/` | раздел «EXG Music» (`music.js` + `music.css`): поиск, «Моя волна», тренды, мини- и полноэкранный плеер; подключается в `forum.src.html` через `{{inc:…}}` |
| `tools/build_forum.py` | сборка `forum.html` из `forum.src.html` + `forum_assets/` (после правок клиента: `python tools/build_forum.py`) |
| `support.py` | ИИ-поддержка / вызов оператора в чатах форума (та же, что в боте) |
| `botcore.py` | общее ядро из `bot.py` (профили, ЛС, значки, пуши). **Сгенерирован, вручную не править** |
| `README.txt` | база знаний для ИИ-поддержки |

## Переменные окружения
Смотрите `.env.example`.

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | токен **того же** бота (форум только отправляет сообщения, polling не запускает) |
| `DATABASE_URL` | да | **та же** БД, что у `jins-bot` |
| `OWNER_ID` | да | тот же Telegram ID владельца |
| `FORUM_URL` | желательно | публичный https-адрес форума (этого сервиса), например `https://jins-forum-main.layero.app`. Без него адрес берётся из запроса |
| `WEBAPP_URL` | желательно | адрес мини-аппа (Render) — для кнопки «Открыть чат» в пушах |
| `GEMINI_API_KEY` | нет | ИИ «Поддержки» |
| `FORUM_KEEPALIVE` | нет | `0` — выключить будилку |

## Запуск
1. Сначала запустите и один раз «прогрейте» `jins-bot` (он создаёт основные таблицы). Если форум стартует раньше, он напишет в лог
   «Ждём, пока основной сервис создаст таблицы…» и сам продолжит, когда они появятся.
2. Создайте сервис (Web Service / Python app) из репозитория `jins-forum`:
   - Build: `pip install -r requirements.txt`
   - Start: `python main.py`
   - Порт: берётся из `PORT` (по умолчанию 10000); health-check: `/health`
   - Переменные: из `.env.example`.
3. Откройте `https://ВАШ-ФОРУМ/forum`. Вход: «Войти через Telegram» → бот подтверждает (`/start forum_КОД`) → форум входит сам.
4. APK: скачайте `https://ВАШ-ФОРУМ/forum/app.html?dl=1` и соберите любым «HTML to APK» (адрес сервера уже вписан).

Локально:
```bash
pip install -r requirements.txt
export BOT_TOKEN=... DATABASE_URL=... OWNER_ID=... FORUM_URL=http://localhost:10000
python main.py     # http://localhost:10000/forum
```

## EXG Music
«Разделы» → «EXG Music»: музыка в стиле Яндекс Музыки. Основной источник — **Яндекс Музыка** (неофициально, библиотека `yandex-music`), запасной — каталог **Jamendo** (независимые исполнители, Creative Commons).
- **Яндекс:** переменная `YANDEX_MUSIC_TOKEN` (как получить — в `.env.example`). Нужен `pip install -r requirements.txt` (добавлен `yandex-music`). Один токен на весь форум — это нарушает правила Яндекса и может привести к блокировке аккаунта; используйте отдельный аккаунт. Без Яндекс Плюс треки приходят отрывками. id трека — `y<число>`, адрес файла временный: звук идёт через `GET /forum/api/music/stream?id=y…` (редирект, лимит 120/мин на IP).
- **Jamendo (запасной):** бесплатный `client_id` с devportal.jamendo.com → `JAMENDO_CLIENT_ID`. Включается, если токена нет, Яндекс вернул ошибку или пустой ответ (на 5 минут).
- Упор на русскоязычное: главная — «Моя волна» (микс русских треков), «Русское — сейчас в тренде» (`lang=ru`, `order=popularity_week`), «Новинки на русском», «Русское — лучшее за всё время», жанровые чипы (теги Jamendo). Зарубежное (`lang=en`) вынесено отдельно: вкладка «Зарубежное» и короткая подборка внизу главной.
- Клиент (`tools/music/music.js`) ходит только через сервер: `GET /forum/api/music/get` (параметры `search, tags, lang, order, limit, offset, groupby`; ответ нормализуется, кэш 10 мин, лимит 60 запросов/мин на пользователя). Звук браузер берёт напрямую с Jamendo (поле `u`) — трафик форума не расходуется; если прямой адрес не открылся, запасной путь `GET /forum/api/music/stream?id=` (редирект на файл).
- Тренды: Яндекс — чарты «Россия»/«Мир» и поиск по жанру; Jamendo — самое слушаемое среди треков с русским текстом (коммерческих хитов там нет).
- Любимое и история — в `localStorage` устройства (`kf_mu_likes`, `kf_mu_hist`), в БД ничего не добавлено. Сохранённое из старой библиотеки (Audius) при загрузке отбрасывается.
- Правки раздела: `tools/music/*`, затем `python tools/build_forum.py`.

### Музыка в профиле
В профиле (и в «Профиль → Изменить») есть карточка «Моя музыка»: виниловый диск с обложкой, название, прогресс, кнопки «Слушать» / «Вперемешку» и список треков. Играет через общий мини-плеер EXG Music.
- Добавить трек: «+» → «Из файлов» (MP3, M4A/AAC, OGG/Opus, WAV, FLAC, WebM; название, исполнитель и обложка берутся из ID3-тегов, иначе — из имени файла) или «Из EXG Music» (поиск, «Любимое», тренды; тап по треку — предпрослушивание, «+» — добавить). Ещё есть кнопка «+» в полноэкранном плеере EXG Music.
- Управление своими треками (⋯): поставить первым, изменить название/исполнителя, удалить. Чужие профили — только слушать и ставить сердечко.
- Хранение: таблица `forum_profile_music` (создаётся автоматически). Файлы лежат в БД (BYTEA), как баннеры; треки EXG Music хранятся ссылкой (id Jamendo; ранее добавленные из Audius больше не играют — их можно удалить из профиля). Тип файла проверяется по содержимому.
- Лимиты: `PROFILE_MUSIC_MAX` (по умолчанию 10 треков на профиль) и `PROFILE_MUSIC_FILE_MB` (по умолчанию 10 МБ на файл). Увеличивая их, помните про размер БД.
- API: `GET /forum/api/pmusic?id=`, `POST /pmusic/add|delete|move|edit`, `GET /pmusic/file/{id}` (с поддержкой Range), `GET /pmusic/cover/{id}`.
- Код: `tools/music/music.js` (`MU.profile`), `tools/music/music.css` (блок «Музыка в профиле»), `forum.py` (блок «музыка в профиле»).

## Звонки
Личные и групповые звонки (аудио/видео) работают как раньше. Состояние звонков хранится в памяти процесса форума, поэтому:
- форум должен работать одним экземпляром (не масштабируйте на несколько реплик);
- при перезапуске/«засыпании» сервиса идущие звонки сбрасываются;
- для звонков между разными сетями (мобильный интернет ↔ Wi-Fi) нужен TURN. Без своего подставляется публичный тестовый (Open Relay) —
  для постоянной работы задайте свой: `CALL_TURN_URLS`, `CALL_TURN_USER`/`CALL_TURN_PASS` или `CALL_TURN_SECRET` (см. `.env.example`).
- звонок работает только пока приложение открыто и сервис не спит; чтобы входящие не терялись, не отключайте будилку.

## База данных
- БД одна на оба сервиса. Если она на Render, возьмите **External Database URL** (внутренний адрес виден только сервисам Render)
  и при необходимости добавьте `?sslmode=require`. Один и тот же URL вставьте в оба сервиса.
- Таблицы `forum_*` создаются автоматически (`CREATE TABLE IF NOT EXISTS`) — переносить данные не нужно, существующие посты и
  аккаунты остаются на месте.

## Известные отличия от «всё в одном процессе»
Две вещи хранились в памяти процесса бота и теперь не видны между сервисами:
- индикатор «печатает…» между форумом и мини-аппом;
- «собеседник сейчас смотрит этот чат» (подавляет push). Из-за этого при переписке форум ↔ мини-апп push может прийти, даже если
  собеседник смотрит чат в другом приложении.
Всё остальное (чаты, сообщения, прочтения, профили, значки, блокировки) хранится в БД и синхронно.

## Мгновенная отправка (оптимистичный интерфейс)
Всё, что отправляет пользователь, сначала показывается на экране, а сервер «догоняет» в фоне. Код — в `forum.src.html` (после правок: `python tools/build_forum.py`).
- **Чаты (личные и группы):** текст, стикеры, GIF, фото, видео и файлы появляются в чате сразу (у фото/видео — превью прямо с устройства). Пока сообщение уходит, рядом с временем крутилка; потом ✓. Сообщения уходят по очереди и по порядку, при `too_fast` запрос повторяется сам. Если не дошло — красная метка «не отправлено», по нажатию: «Отправить ещё раз» / «Удалить».
- **Правка сообщения** применяется сразу, при ошибке возвращается как было.
- **Список сообщений обновляется точечно** (по ключам), а не перерисовывается целиком: картинки не перезагружаются, голосовое не прерывается, чат не мигает. Новый пузырь появляется с короткой анимацией.
- **Чат открывается мгновенно:** последний ответ сервера хранится в памяти, свежие данные подтягиваются фоном.
- **Комментарии, лайки (постов и комментариев), закладки, подписки, правка/удаление комментария, «ответ автору в личку»** — тоже сразу, с откатом при ошибке.
- Сервер не менялся: используются те же запросы `/forum/api/*`.
