# jins-forum — KMBP FORUM (вторая половина проекта)

Форум / соцсеть: лента, разделы, посты, комментарии, группы, каналы, стикеры, GIF, личные сообщения, профили.
Подробное описание функций — `FORUM.md`.

Это **отдельный сервис**, который работает с **той же базой данных**, что и бот (`jins-bot` на Render): аккаунты, профили, значки,
отзывы, личные сообщения («Поддержка» и чаты — те же, что в мини-аппе), блокировки и права админов общие. Всё работает как раньше,
просто в двух процессах.

## Что внутри
| Файл | Назначение |
|---|---|
| `main.py` | точка входа: подключение к БД, запуск веб-сервера форума |
| `forum.py`, `forum_groups.py`, `forum_gifs.py`, `forum_names.py` | сам форум (API `/forum/api/*`, группы, GIF, ссылки `exg/имя`) |
| `forum.html` | клиент форума (собран из `forum.src.html`) |
| `support.py` | ИИ-поддержка / вызов оператора в чатах форума (та же, что в боте) |
| `botcore.py` | общее ядро из `bot.py` (профили, ЛС, значки, пуши). **Сгенерирован, вручную не править** |
| `README.txt` | база знаний для ИИ-поддержки |

## Переменные окружения
Смотрите `.env.example`.

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | токен **того же** бота (форум только отправляет сообщения, polling не запускает) |
| `DATABASE_URL` | да | **та же** БД, что у `jins-bot` |
| `OWNER_ID` | да | тот же Telegram ID владельца |
| `FORUM_URL` | да | публичный https-адрес форума (этого сервиса) |
| `WEBAPP_URL` | желательно | адрес мини-аппа (Render) — для кнопки «Открыть чат» в пушах |
| `GEMINI_API_KEY` | нет | ИИ «Поддержки» |
| `FORUM_KEEPALIVE` | нет | `0` — выключить будилку |

## Запуск
1. Сначала запустите и один раз «прогрейте» `jins-bot` (он создаёт основные таблицы). Если форум стартует раньше, он напишет в лог
   «Ждём, пока основной сервис создаст таблицы…» и сам продолжит, когда они появятся.
2. Создайте сервис (Web Service / Python app) из репозитория `jins-forum`:
   - Build: `pip install -r requirements.txt`
   - Start: `python main.py`
   - Порт: берётся из `PORT` (по умолчанию 10000); health-check: `/health`
   - Переменные: из `.env.example`.
3. Откройте `https://ВАШ-ФОРУМ/forum`. Вход: «Войти через Telegram» → бот подтверждает (`/start forum_КОД`) → форум входит сам.
4. APK: скачайте `https://ВАШ-ФОРУМ/forum/app.html?dl=1` и соберите любым «HTML to APK» (адрес сервера уже вписан).

Локально:
```bash
pip install -r requirements.txt
export BOT_TOKEN=... DATABASE_URL=... OWNER_ID=... FORUM_URL=http://localhost:10000
python main.py     # http://localhost:10000/forum
```

## База данных
- БД одна на оба сервиса. Если она на Render, возьмите **External Database URL** (внутренний адрес виден только сервисам Render)
  и при необходимости добавьте `?sslmode=require`. Один и тот же URL вставьте в оба сервиса.
- Таблицы `forum_*` создаются автоматически (`CREATE TABLE IF NOT EXISTS`) — переносить данные не нужно, существующие посты и
  аккаунты остаются на месте.

## Известные отличия от «всё в одном процессе»
Две вещи хранились в памяти процесса бота и теперь не видны между сервисами:
- индикатор «печатает…» между форумом и мини-аппом;
- «собеседник сейчас смотрит этот чат» (подавляет push). Из-за этого при переписке форум ↔ мини-апп push может прийти, даже если
  собеседник смотрит чат в другом приложении.
Всё остальное (чаты, сообщения, прочтения, профили, значки, блокировки) хранится в БД и синхронно.
